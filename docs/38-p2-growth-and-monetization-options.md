## 0. 结论先行

1. **你列的 5 条方向是对的，但三条关键前提没写进去**：公网入口、账号/授权、支付/许可。没有它们，分享卡二维码出了同一个 Wi-Fi 就是死链，托管 AI 无法计量，MIT 协议下也没法卖 Pro。这三块不是增长功能，是 P2 能不能收钱的地基（见 §4）。
2. **收费边界建议只按「我们的边际成本」画**：本地录音、转写、规则版笔记花的是用户自己的 CPU，边际成本为零 → 永久免费且不限；托管 AI、云端存储/代录、人工精修、团队权限才有成本 → 收费。按这个原则，**「多路」不建议锁进 Pro**（它花的是用户的电，不是我们的钱），锁它只会伤口碑、省不到成本；真正该锁的是云、托管 AI、协作与交付。
3. **9 条里最该先做的是 3 条**：主播返场卡（供给侧增长）、AI 点数包（最低门槛的首购）、录制节点（把「电脑必须开着」变成付费服务）。其余按团队带宽排。
4. **不建议做**：按分钟卖转写（本地转写零成本，收费会被骂）、卖用户数据、课程盗录、纯广告、含云端额度的「终身买断」。
5. **最需要先拍板的不是功能，是许可证**：仓库现在是 MIT（[LICENSE](../LICENSE)），任何人都能 fork 后直接卖。P2 之前必须定「核心开源 + 商业模块闭源」还是「source-available」；否则后面所有订阅都是给别人做嫁衣。

## 1. 增长：3 条

### G1 主播返场卡：把被记录方变成分发方

**形态**

每场结束生成一张「主播返场卡」：

- 本场 3 段高光（时间码 + 一句原话）+ 1 句金句 + 主播昵称 + 本场时长；
- 一张竖版图（复用分享卡 Canvas），底部二维码指向**公网只读笔记页**；
- 主播或运营一键发粉丝群 / 朋友圈 / 视频号评论区；
- 只读页页尾是「用 LiveNotes 记录你自己的直播 → 下载」，带来源码。

**和你的第 1 条有什么不同**

第 1 条是「记录者把笔记分享给朋友」，传播半径取决于记录者自己的人脉；G1 是**让内容的主体（主播/运营）替我们发**，触达的是他的粉丝和同行——这些人本来就在找「怎么把直播做成内容」，转化率完全不同。

**增长回路**

```
运营记录一场 → 返场卡 → 主播发粉丝群 → 粉丝/同行扫码看笔记
→ 下载应用 → 记录自己的直播 → 产出新的返场卡
```

**主播认领（可选但建议）**

- 只读页出现「我是这场主播」入口；认领后显示主播提供的头像/主页链接，并获得本场高光数据；
- 未认领时只显示昵称与文字，不出现头像、直播画面、原声下载；
- 任何主播可提交下架，24 小时内处理。

**落点与工作量**

- 卡面：`app/web/js/sharecard.js` 新增第 4 套模板，2–3 人日；
- 只读页：复用 `/note?share=1`，公网托管依赖 docs/37；
- 认领：需要轻账号与审核，1–2 周（可后置）。

**风险**

- 未经授权商用他人肖像/声音：默认文字 + 昵称，头像与音频需主播主动认领后才出现；
- 平台对「直播内容二次分发」的态度：默认只读、不可下载、带过期与撤销。

**指标**：每张返场卡的扫码打开数、扫码→安装转化（目标 ≥ 3%）、主播认领率、返场卡带来的次日留存。

### G2 免费工具矩阵：用一个具体问题换安装

**形态**

三个不需要安装的公开网页工具，每个只解决一个搜索意图：

| 工具 | 输入 | 输出 | 搜索意图 |
|---|---|---|---|
| 直播回放转文字 | 上传 ≤15 分钟音频，或粘贴回放链接 | 带时间码的样例笔记（摘要 + 3 条要点 + 金句） | 「直播回放怎么转文字」「直播录音转文字」 |
| 开播提醒页 | 粘贴直播间链接 + 邮箱/飞书 | 开播时提醒一次；页面显示最近状态 | 「XX 主播开播提醒」「直播间监控」 |
| 直播话术提取 | 粘贴文字稿 | 开场/逼单/转场/答疑四类话术 | 「直播话术提取」「直播复盘模板」 |

结果页统一水印：「由 LiveNotes 生成 · 下载桌面版，录音不出本机」，带来源码。

**为什么适合我们**

- 三个工具的能力在本地已经跑通（`app/liveprobe.py`、`app/notes.py`、`app/qa.py`），抽一个**受限的**云端版本成本可控；
- 工具本身就是产品 demo，比落地页有说服力；
- 直播运营人群的搜索/社媒行为很明确，长尾词便宜。

**落点与工作量**

- 独立 `site/` 静态站 + 一个轻服务：文件 ≤15 分钟、24 小时删除、IP/邮箱限流、不训练、不公开；
- 不复用主应用进程，避免把公网攻击面带进本地引擎；
- 2–3 周（含域名、备案、隐私文案）。

**风险**

- 被刷：邮箱验证 + 每日限额 + 单文件时长上限；
- 上传内容含他人声音：明示「仅用于本次结果、24 小时删除」，不做内容库、不做公开页；
- 边际成本：只做 15 分钟片段，单次成本可控；超限直接拒绝，不降级成免费长音频。

**指标**：工具 UV → 下载转化 ≥ 3%；单工具获客成本 < ¥5；7 日内激活率。

### G3 服务商分销联盟：让教人做直播的人替你卖

**形态**

面向直播运营培训师、代运营机构、MCN 顾问的联盟计划：

- 专属邀请码/链接，安装或首次付费时绑定，归属 90 天；
- 首年订阅 20–30% 佣金，团队版 15%，续费 5–10%；
- 提供白标报价页、演示账号、学员版模板包；
- 每月结算，签简易分销协议，可开票。

**为什么是他们**

这个人群已经在教「如何拆解对标直播间」，我们的产品就是他们的教具；学员是最高意向的付费用户。相比投流，这是**信任驱动的 CAC**。

**落点与工作量**

- 授权地基里的 `referral_code` 字段 + 云端归属表；
- 分销页与结算表（可先用表格 + 人工）；
- 1–2 周，主要是 BD 与协议，不是开发。

**风险**

- 分销商乱承诺/私自打折：统一定价、统一话术、违规取消资格；
- 退款 clawback：佣金在退款期后结算。

**指标**：联盟付费占比、CAC、退款率、联盟带来的团队版线索数。

## 2. 变现：4 条

### M1 AI 点数包：把「3 次试用」接住

**要解决的问题**

3 次免费用完，用户面对两个选择：订阅（决策重）或流失。中间缺一个 **¥9.9–29 的低门槛首购**。

**形态**

- 点数钱包：1 点 = 1 场标准 AI 笔记（≤2 小时）；周报、问笔记、重生成按点消耗；
- 点数 12 个月有效；订阅每月含点数，超出可加购；
- 团队版点数池共享，管理员可分配；
- 明细页：每一笔消耗对应哪一场、哪个任务、什么时间。

**定价假设（待测）**

| 包 | 价格 | 单价 |
|---|---|---|
| 体验包 | ¥19 / 10 点 | ¥1.9/场 |
| 常用包 | ¥49 / 30 点 | ¥1.6/场 |
| 重度包 | ¥129 / 100 点 | ¥1.3/场 |
| Pro 月付 | ¥49/月，含 60 点 | 超出 ¥1.2/点 |

> 单场成本随模型与直播时长变化。上线前用 10 场真实数据测一次「单场平均 token 成本」，再定点数价格；不要拍脑袋。

**为什么适合**

- 调度器已经有 token 预算、预留与跨重启累计（[app/scheduler.py:409](../app/scheduler.py:409)），把「本地上限」扩展成「云端额度校验」即可，不用重写计费；
- 对用户用「场/点」计价，不用解释 token；
- 点数包是订阅的踏板，不是替代品。

**落点与工作量**

- `app/quota.py` + 云端 `/v1/quota/consume` + 离线宽限（本地记欠账，联网补扣）；
- 失败、降级、重复提交不扣点；每笔可申诉；
- 地基完成后 2–3 周。

**风险**

- 定价与模型成本倒挂：按最贵模型设单场上限，超出降级到便宜模型并明示；
- 点数纠纷：所有扣点必须有任务 id 与明细，支持一键退还。

**指标**：试用→首购转化（目标 ≥ 8%）、点数包复购率、点数消耗分布、首购后 30 天转订阅率。

### M2 录制节点 / 云端代录：把「电脑必须开着」变成付费服务

**要解决的问题**

本地产品的天花板是「电脑必须开着」。凌晨开播、出差、多房间同时开播，都会漏录——这是重度用户最愿意付费的点。

**两种形态，建议先做 B**

| 形态 | 做法 | 风险 | 建议 |
|---|---|---|---|
| A 云端代录 | 我们的服务器 7×24 抓公开直播间，第二天同步到本地 | 平台 ToS/风控高，服务端 IP 容易封；带宽与合规成本 | 暂缓，需法务评估 |
| B 录制节点 | 用户把旧电脑/NAS/迷你主机装成「录制节点」，我们卖节点授权与同步服务；采集仍在用户自己的网络与账号环境里 | 低得多；用户自己承担设备与网络 | **先做** |

**B 的产品形态**

- 一个精简的「节点模式」安装包：无界面、开机自启、只做采集与上传；
- 主应用里能看到节点在线状态、磁盘、正在录哪几路；
- 卖的是「节点授权」：¥19/节点/月（含 3 路）、¥49/节点/月（含 10 路）；
- 录音先落节点本地，再按 docs/37 的方案 A 上传；断网不丢，恢复后续传。

**为什么适合**

- 完全符合本地优先与「不为我们的边际成本之外收费」；
- 复用现有采集、看门狗、自动收尾与云存储方案；
- 对用户是「不用一直开着主力电脑」，对我们是可控的订阅收入。

**落点与工作量**

- 节点模式：现有引擎加 `--node` 启动参数 + 托盘/服务化 + 节点心跳（2–3 周）；
- 节点管理页 + 授权校验（1–2 周）；
- 云同步复用 docs/37 的 P1 阶段（1 周）。

**风险**

- 用户设备安全：节点只监听内网、默认无公网入口，上传用短期签名；
- 平台风控：仍是用户自己的网络与账号，但多房间高频采集需限速与告警；
- 支持成本：节点故障排查 → 诊断包 + 远程日志开关。

**指标**：节点付费数、节点在线率、每节点录制小时、节点用户续费率（目标 ≥ 70%）。

### M3 竞品直播监测：卖给「靠直播吃饭」的团队

**形态**

- 选 5–20 个对标直播间，自动记录；
- 每周一份竞品简报：他们讲了哪些品、什么话术、什么时段、做了什么活动、哪几段值得听；
- 支持按话题/话术/商品维度与自己对比；
- 只做公开直播间、机构内部使用、不提供原声批量导出。

**客户**

品牌直播运营、代运营机构、产业带商家、投流团队——不是普通观众。与 MCN 团队版的区别：**团队版卖协作与席位，M3 卖情报与对比**。

**定价假设**

- ¥999/月：10 个房间、周报、3 个席位；
- ¥2999/月：20 个房间、日报/周报、10 个席位、导出；
- 年付 8 折。

**为什么适合**

`follows` 底座、周报叙事、证据链已经齐了；竞品监测本质是「关注从 3 个扩到 20 个 + 对比视图 + 定时交付」。

**落点与工作量**

- follows 分档限额、对比报告模式（`app/report.py` 增加 compare）、定时推送；
- 依赖 M2 的节点/代录能力；4–6 周。

**风险**

- 平台 ToS 与「不正当竞争」边界：只记录公开内容、只做内部参考、不做话术库转售；
- 客户预期：卖「趋势与对比」，不卖「抄话术」；
- 数据保留：默认 30 天，客户可配。

**指标**：机构付费数、监测房间数、周报打开率、续费率。

### M4 精修交付：先卖服务，再产品化

**形态**

高价值场次（招商会、私域发售、行业峰会、连麦访谈）的「人工 + AI」精修包：

- 逐字稿校对、说话人实名、术语纠正；
- 要点提炼、金句卡、复盘文档、分享包；
- 48 小时交付，含 1 次修订；
- ¥999–4999/场，按场次时长与交付物分档。

**为什么先做**

- 不用等产品成熟就能验证「谁愿意为结果付多少钱」；
- 交付过程会直接告诉我们哪些步骤该产品化（校对、实名、模板、导出、分享卡）；
- 高毛利、可先由创始人手工做，不需要研发。

**落点与工作量**

- 无产品开发；用现有 `/reader`、校对、`/api/export`、分享卡能力，人工补；
- 需要一份 SOP、报价单、交付模板、授权确认书；
- 每月限 5–10 场，避免吞噬主线。

**风险**

- 不可规模化、质量波动：限定场次、标准 SOP、只接能授权的内容；
- 与免费用户争时间：优先级低于产品迭代，排期外接单。

**指标**：毛利、交付时长、复购率、从服务转订阅/团队版的比例、被产品化的功能数。

## 3. 扩张：2 条

### E1 模板与工作流市场：把「模板」从功能变成生态

**形态**

模板 = 四样东西的组合，不是一张皮肤：

1. **章节结构**（schema）：例如「直播复盘」= 本场目标 / 流量曲线 / 转化节点 / 话术 / 下一场动作；
2. **生成提示词**：每个章节要模型做什么、证据从哪来；
3. **导出布局**：Markdown 标题层级、表格、分享包内容；
4. **分享卡样式参数**：字体、留白、颜色、二维码位置。

创作者可发布模板（¥9–99），平台抽 30%；模板作者有主页，可带自己的社群/课程。官方先出 8 套：直播复盘、课程笔记、招商会、连麦访谈、竞品周报、选品会、私域发售、会议纪要。

**和你第 5 条的区别**

第 5 条是「官方内置模板」；E1 是「UGC 市场 + 分成」，解决模板从哪来、谁维护、怎么传播。**先做官方 8 套，再邀请 10 位创作者内测，不要一上来开市场。**

**为什么适合**

这个用户群（运营/培训师）本身就靠模板和方法论吃饭，有动力发布；模板是最轻的内容资产，不需要云端算力。

**落点与工作量**

- `app/templates.py`：schema 校验、安装、版本、回滚；笔记生成读取模板；
- 分享卡模板参数化（现在三套是写死的绘制函数，见 `app/web/js/sharecard.js`）；
- 市场端需要云端（列表、购买、签名包、作者分成）；
- 本地 1–2 周，市场端 3–4 周。

**风险**

- 模板质量参差/侵权：审核 + 退款 + 举报；
- 模板注入恶意 prompt：只允许声明式字段，不允许任意代码/URL；
- 模板与产品版本不兼容：schema 带 `min_app_version`。

**指标**：模板安装率、付费模板转化、作者数、使用模板用户的留存提升。

### E2 白标 / API 授权：把能力卖给已经有客户的人

**形态**

两种交付：

1. **白标**：给直播培训 SaaS、私域工具、MCN 系统一个「记录 → 笔记 → 周报」模块，贴他们的品牌，按席位/年授权；
2. **API**：按调用量卖转写、笔记、周报生成（异步任务 + webhook + 签名回调）。

**定价假设**

- 白标：¥8–20 万/年 + 席位费；含 1 次私有化部署；
- API：¥0.3–1/场（按分钟阶梯），年框预付；
- 企业内网：买断 + 年维保 15–20%。

**为什么适合**

核心引擎与证据链已经在本地跑通，`app/server.py` 本身就是 HTTP API；打包成 headless 服务不难。B2B 单笔大、CAC 低，且能反哺产品稳定性。

**落点与工作量**

- 多租户配置、API Key、任务回调、品牌资源、隔离与审计；
- 先做「单租户私有化」再接「多租户 SaaS」；
- 6–10 周，视客户需求。

**风险**

- 定制需求吞噬团队：只做标准模块，深度定制单独报价；
- 数据隔离与 SLA：合同写清楚；
- 开源许可：见 §4.2，白标必须建立在商业许可之上。

**指标**：签约数、ACV、交付周期、续约率。

## 4. 地基：前 9 条的前提

### 4.1 授权、计费与试用状态机

- **账号可轻**：手机号/邮箱 + 设备码；云端只存「权益、额度、订单、归属码」，**不存笔记与音频**；
- **授权**：Ed25519 签名的离线 license（plan、到期、设备数、额度），7–30 天离线宽限；企业内网用激活码；
- **试用状态机**：未激活 → 试用 → 受限（本地不限，AI 停）→ Pro/Team；降级不删数据、不锁导出、不锁分享；
- **支付**：微信/支付宝（需主体与商户号）、对公转账、发票；
- **埋点**：付费漏斗事件（曝光/点击/下单/支付/退款）走云端订单侧；产品内仍按 docs/36 §13 只存本地、可自愿上传聚合。

**工作量**：3–4 周（含支付接入与对账）。

### 4.2 许可证策略：商业化第一决策

当前是 MIT（[LICENSE](../LICENSE)）：任何人都可以 fork、改名、直接卖，包括把我们的云端额度接过去。P2 之前必须三选一：

| 方案 | 含义 | 优点 | 缺点 |
|---|---|---|---|
| A Open core | 核心继续 MIT，商业模块（云、托管 AI、团队、市场）闭源 | 社区与信任不受损；商业边界清楚 | 需要拆分仓库/模块边界 |
| B Source-available | 源码可见，但禁止商业转售（如 BUSL/自定义） | 防止直接 fork 售卖 | 不再是 OSI 开源，社区可能反弹 |
| C 双许可 | 社区版 MIT/GPL，商业版另签 | 企业客户接受度高 | 法务与销售成本高 |

**建议 A**：本地引擎继续 MIT，云端与团队能力闭源；在 README 与下载页写清楚「哪些是开源、哪些是商业服务」。这比事后改协议体面，也不影响现在的社区传播。

### 4.3 公网入口

分享页、返场卡、工具矩阵、手机只读、云端同步都需要一个公网入口。docs/37 已给「对象存储 + 预签名 + 分享页」的路线；**没有它，第 1 条就只是局域网玩具**。优先级应高于任何增长功能。

### 4.4 计量口径

对用户统一用「场 / 点 / 席位 / 节点」，内部映射 token 与存储。调度器已有预算与预留（`reserve` / `budget_status`），扩展成云端配额校验即可，不要重写一套计费。

## 5. 优先级与路线

| 阶段 | 做什么 | 为什么这个顺序 | 日历（1–2 人） |
|---|---|---|---|
| **P2.0 收钱地基** | 许可策略、授权/试用状态机、支付、公网分享页、付费漏斗 | 没有这些，后面每一条都收不到钱 | 6–8 周 |
| **P2.1 首购与传播** | G1 返场卡、M1 点数包、M4 精修（手工）、G3 联盟 | 最低成本验证「谁愿意付、为什么付」 | 6–8 周（可与 P2.0 部分并行） |
| **P2.2 服务化** | M2 录制节点、G2 工具矩阵、E1 模板市场 v1 | 把订阅从「功能」升级为「服务」 | 8–12 周 |

## 7. 指标与实验

### 7.1 付费漏斗

```
安装 → 首次记录 → 第 2 次打开 → 触发 AI 试用 → 触达限制
→ 首购（点数包/Pro）→ 续费 → 推荐/团队扩展
```

每一步都要有分子分母；没有分母的「增长」都是感觉。

### 7.2 每条方案的领先指标

| 方案 | 领先指标 | 判定继续/停止 |
|---|---|---|
| G1 返场卡 | 扫码打开率、扫码→安装 | 安装转化 < 1% 就停 |
| G2 工具矩阵 | UV→下载、单客成本 | CAC > ¥15 就停 |
| G3 联盟 | 联盟付费占比、退款率 | 退款率 > 15% 就停 |
| M1 点数包 | 试用→首购、复购 | 首购 < 3% 就改试用策略 |
| M2 节点 | 节点付费、在线率 | 在线率 < 90% 先修稳定性 |
| M3 监测 | 机构签约、周报打开 | 3 个月签不下 3 家就停 |
| M4 精修 | 毛利、转订阅率 | 交付超过 3 人日/场就涨价或停 |
| E1 模板 | 安装率、付费转化 | 官方 8 套用不起来就不开市场 |
| E2 白标 | 签约、ACV | 单客户定制 > 30 人日就停 |

### 7.3 先跑的 4 个实验

1. 试用：3 场 AI vs 7 天全功能，看首购率；
2. 首购价：¥19/10 点 vs ¥29/10 点，看转化与退款；
3. 返场卡：有主播署名 vs 无署名，看扫码与安装；
4. 年付：8 折 vs 送 2 个月点数，看续费与现金流。

## 10. 一句话总结

**增长不是再做一个分享按钮，而是让「被记录的主播」替我们发卡、让「教人做直播的人」替我们卖、让「搜一个问题的人」先用到结果；商业化不是再加一个 Pro 开关，而是按边际成本画免费边界，用点数包接住试用、用录制节点接住「电脑必须开着」、用竞品监测和白标接住高客单；而这一切之前，先把许可、授权、支付和公网入口这四块地基打完。**
