# 30 · 场面化高光与主线叙事周报

> 状态：已落地（高光榜 / 飞书推送 / 周报）。复盘模板暂未改。
> 代码：`app/scenes.py`（新）、`app/highlight.py`、`app/report.py`、`app/store.py`、
> `app/live.py`、`app/web/highlights.html`、`tools/weekly_report.py`

## 为什么改

旧版高光和周报都是「把逐字稿按分数排一遍」：

- 高光按单句打分，离开上下文常常什么都不是（「就是我大概听了一下」也能上榜）；
- 周报按场次列「要点 / 原话」，读者看到的是转录，不是编辑过的内容；
- 两个产物都缺主张：没有一句话告诉你「这周发生了什么」，只有一堆句子。

这次把产出分成三层，越往下越自由，但每层都必须能回到上一层：

| 层 | 内容 | 约束 |
| --- | --- | --- |
| 事实层 | 逐字稿、时间码、说话人 | 只来自 ASR / 校对结果 |
| 主张层 | 钩子、标签、主线标题与正文 | 必须绑定原文；数字不许超纲 |
| 编辑层 | 排序、小标题、导语、金句 | 可以重组，但不能新增事实 |

## 一、场面化高光

### 切段（纯规则，0 token）

`app/scenes.py` 把整场按三种边界切成 30~90 秒的「场面」：

- 静默超过 `LIVENOTES_SCENE_GAP_S`（默认 8 秒）；
- 已经聊了 `LIVENOTES_SCENE_MIN_S`（20 秒）以上，且话题标签变了；
- 单段超过 `LIVENOTES_SCENE_MAX_S`（90 秒）。

短于 20 秒或少于 12 字的段，若与上一段间隔不超过 `LIVENOTES_SCENE_MERGE_GAP_S`
（12 秒），并回上一段，避免把一句插话切成独立场面。

### 选段与写钩子

1. 每段里挑一句「有信息量」的句子做峰值：必须是 `substantive` / `question_consult`，
   至少 8 字，分数过 `highlight.TH`；语气词不算。
2. 段的分数 = 峰值分 + `0.12 × min(4, 句数-1)`，奖励有来有回的段落。
3. 候选段沿用 `highlight._mix` 的双轴配额（信息 / 情绪），避免整场都是同一种戏。
4. 模型只做「编辑」，不做「发现」：给 12 个候选段，让它挑 3 段并写
   `hook`（钩子）、`quote`（原声）、`tag`（金句/冲突/干货/反转/问答/故事/看点）、
   `why`（一句理由）。
5. 证据闸门：`quote` 必须能在该段原文里逐字找到（去标点后比较）；找不到时按
   相似度 0.6 回退到最接近的一句原话，仍不达标就丢弃这条模型选择。

模型失败、未配置、预算不足都退回规则版：钩子取峰值句的第一个短分句，标签按
数字 / 问答 / 打断 / 长度判断。`build()` 的返回值里带 `engine` 和 `llm_error`，
页面和日志能看出来这次是不是模型版。

### 落库与展示

`highlights` 表新增 `hook` / `tag` / `quote` / `scene_json` 四列（启动时自动迁移）。
`scene_json` 存整段台词，高光卡片可以展开「这场戏的上下文」，不再只有一句话。

- `POST /api/highlights/build` 接受 `limit`（最多 20）和 `llm=false`；
- 高光榜卡片显示：标签、钩子、「原声」、理由、可展开的场面、播放/阅读/反馈；
- 飞书推送与 `_digest_text` 用场面起点作为回听时间，推送的是 `[标签] 钩子` +
  原声，不再推一句孤立的转录；
- 收工回顾用 `scenes.session_events()`：只算不写库、不调模型，0 token。

### 调参

| 环境变量 | 默认 | 作用 |
| --- | --- | --- |
| `LIVENOTES_SCENE_GAP_S` | 8 | 静默切段阈值（秒） |
| `LIVENOTES_SCENE_MIN_S` | 20 | 最短场面；切话题也要求至少这么长 |
| `LIVENOTES_SCENE_MAX_S` | 90 | 最长场面 |
| `LIVENOTES_SCENE_MERGE_GAP_S` | 12 | 短段并回上一段的最大间隔 |
| `LIVENOTES_SCENE_LIMIT` | 3 | 默认产出几条 |
| `LIVENOTES_SCENE_CANDIDATES` | 12 | 送给模型判断的候选段数 |

## 二、主线叙事周报

### 证据池

把一周内每场的「要点」和「场面化高光」压成一份证据池，每条有整数 id、场次、
日期、说话人、时间、原文、话题。相同原话去重。周报的每句话都必须引用池里的 id。

### 模型产出

一次调用返回：

- `lead`：一到两句导语；
- `storylines`：3~5 条跨场主线，标题是 12~18 字的判断句（不是「薪资与谈判」
  这类话题标签），正文 80~140 字，每条至少 2 条证据；
- `quotes`：3 条金句，只给 evidence_id；
- `questions`：材料里确实没有答案的问题。

### 闸门

`_gate_narrative()` 逐条检查，不过就整条丢弃：

1. 证据 id 必须存在，每条主线至少 2 条；
2. 一周多场时，每条主线的证据必须来自至少 2 个不同场次——否则还是「某场说了什么」；
3. 正文和标题里出现的数字，必须能在被引用原话、统计数字、日期范围或 0~10 的
   结构性小整数里找到；
4. 金句优先选陈述句，问句只在没有陈述句时使用；
5. 一条主线都过不了，就判定本次模型结果不可用，退回规则版。

### 规则版兜底

没有模型 / 未配置 / 调用失败 / 闸门全灭时，按话题分组：只保留覆盖至少 2 场的
话题，每组取 2~3 条证据，尽量不重复引用；没有这样的跨场话题时，退回
「本周最值得回看的三段」+ 本周金句 + 还没答案的问题。兜底同样带证据行和数字，
不会出现无出处的判断。

### 渲染

```
# 直播周报 · 11-09 ~ 11-15
> …
导语

## 本周主线
### 一、所有人都在问「现在要不要动」
正文
- 「原话」—— 主播 · 《场次》 · 0:10

## 本周金句
1. 「原话」—— …

## 还没答案的问题
- …

## 场次与回放
- 11-11 周三 · 《…》 · 1 小时 · 话题 · 妙记链接

## 本周数字
- 场次 / 总时长 / 素材覆盖 / 高频话题
```

`report.build(..., use_llm=False)` 或 `python tools/weekly_report.py --no-llm`
可强制走规则版，用于离线、省 token 或排查模型问题。返回值 `info["narrative"]`
带 `engine`（`llm(...)` / `rules`）和 `reason`（兜底原因）。

## 测试

- `tests/test_scenes.py`：静默/话题切段、规则钩子与标签、模型编造原话被拒、
  合法原话被接受、落库字段、`session_events` 0 token；
- `tests/test_report.py`：规则版主线/金句/问题渲染；模型版主线、导语、问题；
  编造数字（「999 万」）导致整篇回退规则版。

## 已知限制

- 切段只看静默、话题标签和时长，没有语义分段；快速换话题但话题标签未更新时，
  会切得偏粗。
- 模型挑段仍可能偏爱「情绪高」的段；双轴配额只是保证候选里有干货，最终取舍在模型。
- 跨场主线依赖模型；规则版只能按共享话题分组，没有共同话题时会退化成「本周精选」。
- 复盘（retro）仍是原模板，本次只改了周报。
