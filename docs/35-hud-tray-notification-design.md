# 35 · 极简记录 HUD + 托盘 + 通知 设计

> 面向：产品、设计、实现
> 依据：[32 · 桌面客户端产品打磨清单](32-desktop-product-polish.md) §3.3 / §3.6，[33 · P0 迭代方案](33-p0-hud-and-note-iteration-plan.md) §3
> 结论时间：2026-11-15
> 一句话：**HUD 让用户敢离开，托盘让用户随时知道还在录，通知负责在出事和出结果时把人叫回来。**

---

## 0. 一页纸

### 0.1 这次交付什么

**A. 极简记录 HUD**

用户点「开始记录」后，界面从监控台切成一张安静的记录卡：大计时、几位说话人、最近几句字幕、暂停 / 标记 / 结束。它只回答三个问题：在录吗？录了多久？出事了吗？

**B. 托盘**

关掉窗口后录音继续，托盘图标和 tooltip 持续显示「正在记录 00:42:10」；右键菜单可以打开记录卡、暂停、标记、结束；退出有确认。

**C. 通知**

断流、恢复、静音、下播、笔记生成、生成失败、引擎异常、磁盘不足，都有对应的人话通知；通知可点击回到对应界面；应用内通知中心兜底；通知可分类关闭。

**D. 收尾衔接**

「结束并生成笔记」后进入三步收尾进度卡（保存录音 / 整理说话人 / 生成笔记），可以后台进行；完成后如果用户在电脑前直接进笔记页，否则发通知。失败保留录音和逐字稿，给重试和「先看原文」。

### 0.2 不做什么（本迭代）

- 不做独立的置顶悬浮小窗（always-on-top pill）；HUD 是主窗口内的视图，托盘负责「离开」。
- 不做多路批量托盘操作；多路时只操作最近一路，其余走多路视图。
- 不做通知分组、筛选 tab、通知历史搜索、自定义通知声音。
- 不做手机推送、云通知、邮件通知。
- 不做笔记页本身（33 方案 B）；本迭代只做收尾后的跳转和通知。
- 不做录屏、视频切片、直播弹幕、礼物统计。
- 不做「每小时提醒还在录」这类持续打扰。

### 0.3 与 33 的关系

[33](33-p0-hud-and-note-iteration-plan.md) §3 已经给出了 HUD / 托盘 / 通知的实现级方案（API、表结构、托盘协议、文件落点）。本文是**产品与交互设计层**，在它之上补齐：

1. HUD 从首页进入的衔接（首页 → 预检 → HUD）；
2. Windows 通知的展示、权限、首次投递、重启后不重播；
3. 睡眠 / 恢复、引擎崩溃、磁盘满、关机等边界；
4. 多路时的明确降级；
5. 全量文案、验收和埋点。

如果两文冲突：**产品口径以本文为准，技术落点以 33 §3.9 为准。**

### 0.4 验收口径

- 干净 Windows 11：开始记录 → 3 秒内进入 HUD → 关窗 → 托盘可见计时 → 断流 45 秒内收到通知 → 结束 → 收尾 → 笔记完成通知 → 点击打开笔记；全程不需要命令行。
- 关窗 5 分钟后仍有新字幕、有音频落盘；托盘 tooltip 计时正确。
- 暂停时计时停住；恢复后继续；标记写入 `marks`。
- 通知同一事件不重复；应用在前台时只出应用内提示，不弹系统通知。
- 通知权限关闭时，通知中心仍完整；重开应用不重播旧通知。
- 退出时有录音必须确认；取消后录音不中断。
- HUD / 托盘 / 通知里不出现「采集、断流、ASR、聚类、token、阶段码」等工程词。

## 1. 设计命题

### 1.1 四个动作

用户真正会做的只有四件事：

```
开始记录 → 离开 → 收到结果 → 回来读
```

### 1.2 现在每一步都断了一次

| 动作 | 现在发生什么 | 断点 |
|---|---|---|
| 开始记录 | 进入「收听」工作台：房间列表、波形、实时字幕、未转写分钟、重叠秒数 | 用户以为自己在看监控，不知道该盯哪里 |
| 离开 | 关窗会收进托盘，但托盘菜单是诊断向的，不显示录了多久 | 不敢关；关了不知道还在不在录 |
| 收到结果 | 只有飞书推送；本地没有通知 | 录完不回来看，笔记等于没生成 |
| 回来读 | 打开工作台：筛选器 + 逐字稿表格 + 侧栏总结 | 没有一个「一篇笔记」的完成态 |

### 1.3 四个界面各管一段

| 界面 | 管什么 | 用户问题 |
|---|---|---|
| HUD | 记录中 | 在录吗？录了多久？出事了吗？ |
| 托盘 | 离开后 | 还在录吗？我能暂停 / 结束吗？ |
| 通知 | 出事 / 出结果 | 发生了什么？我该点哪里？ |
| 笔记页 | 回来读 | 这场讲了什么？哪段值得回听？ |

这三件事必须一起成立，用户才敢把一场两小时的直播交给它。

### 1.4 信任链

```
看得见的计时
  + 关窗后的持续感知
  + 出事前的主动提醒
  + 失败时的人话和兜底
  = 敢离开
```

任何一环缺失，用户就会回到「开着窗口盯着看」的旧习惯。

## 2. 目标与原则

### 2.1 目标

1. **记录中不用盯**：关掉窗口也知道在录、录了多久、有没有出事。
2. **出事有人管**：断流、静音、引擎异常、磁盘不足，用户先于「发现少录两小时」知道。
3. **录完马上有产物**：结束记录后自动生成笔记，不需要再点「AI 分析」。
4. **通知不打扰**：只发可行动的事件；同一事件不重复；前台不弹系统通知。
5. **失败不吓人**：录音和逐字稿优先保住；页面给人话和下一步，不显示堆栈 / 阶段码。

### 2.2 设计原则

1. **记录中只回答三个问题。** 波形、队列、token、重叠、未转写分钟全部不进 HUD。
2. **一个主按钮。** HUD 只有「结束并生成笔记」是实心按钮；暂停 / 标记是次级。
3. **通知必须可行动。** 每条通知要么能打开对应页面，要么能重试；纯告知型默认少发。
4. **前台用应用内提示，后台才用系统通知。** 用户正在看应用时，不要再弹一个 Windows 通知。
5. **失败要说清楚「什么还在」。** 「笔记没生成成功，录音和逐字稿都在」比「任务失败」有用。
6. **不偷焦点。** 系统通知点击才打开窗口；通知本身不抢当前应用焦点。
7. **工程词不上界面。** 采集 → 录音；断流 → 听不到声音；聚类标签 → 说话人；场次 → 这场直播；token → 隐藏。

### 2.3 指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 关窗后继续录 | 关窗 5 分钟后仍有新音频块 / 新定稿 | 100% |
| 断流发现时延 | 音频中断到用户收到通知 | ≤ 45 秒 |
| 结束到笔记可读 | 点结束到笔记页数据 ready，P95（20 分钟场，LLM 正常） | ≤ 90 秒 |
| 笔记打开率 | 生成完成通知 / 页面被打开 | ≥ 60%（种子用户） |
| 通知重复率 | 同一事件重复通知 | 0 |
| 通知点击率 | 点击通知 / 展示通知 | ≥ 25% |
| 误以为没在录 | 可用性测试中用户说「不知道还在录」 | 0/10 |
| 崩溃-free | 无崩溃会话 | ≥ 99% |

## 4. HUD 设计

### 4.1 形态决策：壳内记录卡，不是独立悬浮窗

**v1 不做独立置顶小窗。** 理由：

- 独立窗口要处理置顶、焦点、DPI、任务栏、多屏、窗口生命周期，成本高；
- 用户「离开」的诉求由托盘 + 通知覆盖，不需要一个一直挡在屏幕上的小条；
- 先把记录卡本身做对，比多一个窗口更能建立信任。

**但 HUD 支持两种密度：**

| 模式 | 触发 | 表现 |
|---|---|---|
| 标准 HUD | 主窗口默认 | 计时、统计、字幕、操作、安心条 |
| 紧凑 HUD | 窗口宽度 < 640px，或用户点「紧凑」 | 隐藏导航 / 侧栏，计时缩小，字幕 4 行，操作图标 + 文字 |

**P1 再评估置顶小窗**：如果真实用户反馈「想一边看直播一边看计时」，再做一个 360×220 的置顶窗，复用同一套状态和事件。v1 不预留半成品入口。

### 4.2 布局

```
┌──────────────────────────────────────────────────────────────────┐
│  ● 正在记录        阿哲 · 今晚聊中小主播的选品       [—] [□] [×]  │
│                                                              │
│                                                              │
│                        00:42:10                              │
│               2 位说话人 · 已转写 1,284 句                    │
│                                                              │
│       [ ⏸ 暂停 ]      [ 📍 标记此刻 ]      [ 结束并生成笔记 ]   │
│                                                              │
│  最近在说                                                     │
│  ┌──────────────────────────────────────────────────────────┐ │
│  │ 主播  00:42:03                                           │ │
│  │ 所以这个品类的核心其实是复购，不是拉新……                  │ │
│  ├──────────────────────────────────────────────────────────┤ │
│  │ 嘉宾  00:41:58                                           │ │
│  │ 对，我们上个月的数据也是这样……                            │ │
│  └──────────────────────────────────────────────────────────┘ │
│                                                              │
│  已标记 2 处 · 关掉窗口也会继续记录 · 音频只存本机              │
└──────────────────────────────────────────────────────────────────┘
```

**布局规则**

- 内容区最大宽度 760px，垂直居中偏上；窗口再大也不把计时拉满屏。
- 计时是第一视觉层级：72–96px，等宽数字（`font-variant-numeric: tabular-nums`），避免每秒抖动。
- 状态行在计时上方；统计行在计时下方；操作在统计行下方；字幕在操作下方。
- 主按钮「结束并生成笔记」放在操作组最右 / 最显眼位置；左侧两个次级按钮用幽灵样式。
- 底部安心条固定一行，不随内容滚动。
- 窗口控制保留系统 / 自绘按钮；「最小化」是任务栏最小化，「关闭」在记录中是收进托盘。

### 4.3 模块规则

| 模块 | 规则 |
|---|---|
| 状态行 | 圆点 + 人话：正在记录 / 已暂停 / 听不到声音 / 正在收尾 / 直播可能结束了；右侧显示房间名，可截断 |
| 计时 | 取 `/api/live/status` 的 `elapsed`（音频累计），每秒刷新；**不要用墙钟**，否则暂停会继续涨 |
| 统计行 | `N 位说话人 · 已转写 M 句`；只在记录中显示；不显示未转写分钟、重叠秒数、token、队列深度 |
| 字幕 | 最近 6–8 句定稿；说话人颜色点 + 名字 + 时间码；新句从底部进入；不做表格、筛选、分类 |
| 识别中 | 末尾灰色一行「识别中…」显示当前临时结果；定稿后替换，不累积 |
| 主操作 | 「结束并生成笔记」唯一实心按钮；点击二次确认 |
| 次操作 | 暂停 / 继续；标记此刻；看画面（切到现有页面舞台，不新开窗口） |
| 打点 | 折叠显示最近 3 个标记；点击从该时间点播放；不在 HUD 里编辑 |
| 安心条 | 「关掉窗口也会继续记录 · 音频只存本机」；首次进入 HUD 时额外用一次 toast 说明 |
| 房间名 | 显示「主播名 · 直播标题」；用户改过名优先；不显示房间号 / 采集方式 |

**明确从 HUD 拿掉**：波形画布、采集阶段码、房间列表、筛选、分类标签、重叠提示、token、说话人聚类编号、监控墙入口、未转写分钟、队列深度。

### 4.4 HUD 状态机

| 状态 | 触发 | HUD 表现 | 托盘 | 通知 |
|---|---|---|---|---|
| 启动中 | 点开始记录后 | 「正在打开直播间…」「正在连接声音…」+ 取消 | 「正在启动」 | 不发 |
| 记录中 | 首块音频 / 有定稿 | 计时、统计、字幕、暂停 / 标记 / 结束 | 计时 + 红点 | 不发 |
| 已暂停 | 点暂停 | 计时变灰 + 「暂停中，这段不会被记录」+ 继续 | 「已暂停」 | 不发；30 分钟后应用内提醒一次 |
| 安静 | `idle_s > 30s`（没人说话，但音频块正常） | 顶部轻提示「已经 N 秒没听到人说话，直播还开着吗？」+ 看画面 | 正常 | 不发 |
| 断流 | `last_chunk_ago_s > 30s` | 红色提示「听不到声音了（连接断开 N 秒）」+ 重新连接 / 结束并保存 | 警告图标 | 45 秒内发一次 |
| 连续静音 | 全零音频超过 2 分钟 | 红色提示「连续 N 分钟没有声音」+ 看画面 / 结束并保存 | 警告图标 | 发一次 |
| 直播结束 | 看门狗判定下播 | 「直播可能已经结束了」+ 生成笔记 / 继续记录 | 正常 | 发一次 |
| 收尾中 | 点结束后 | 三步进度：保存录音 / 整理说话人 / 生成笔记；可后台 | 「正在生成笔记」 | 不发，直到完成 |
| 生成失败 | 笔记任务失败 | 「笔记没生成成功：<人话>」+ 重试 / 先看原文 | 警告图标 | 发一次 |
| 完成 | 笔记 ready | 「笔记已生成」+ 打开笔记 / 再记一场 | 正常 / 笔记就绪 | 发一次 |
| 引擎异常 | 壳检测到引擎退出 / 重启 | 「记录程序断开了」+ 重试 / 检查问题 | 警告图标 | 发一次 |

**状态转换规则**

- 任何失败状态都必须保留「录音和逐字稿还在」的说明，除非确认丢失。
- 「安静」不是错误，不发通知；「断流」和「连续静音」才是。
- 断流恢复后显示「声音恢复了」，并允许继续；不要自动结束。
- 直播结束是「可能」，不是「确定」；给「继续记录」兜底误判。
- 收尾中不显示录音计时；显示进度和「可以关掉窗口」。
- 生成失败后页面不跳走；用户仍能「先看原文」。
- 完成状态如果用户不在电脑前，只发通知，不自动抢占前台。

### 4.5 操作与确认

| 操作 | 行为 |
|---|---|
| 暂停 | 立即暂停；计时停住；状态行变「已暂停」；托盘同步；不弹确认 |
| 继续 | 恢复；计时继续；不发通知 |
| 标记此刻 | 把当前音频时间写入 `marks`；toast「已标记 00:42:31」；最近标记 +1 |
| 看画面 | 切到现有「页面」舞台；HUD 可通过返回键回来；没有可显示页面时隐藏此操作 |
| 结束并生成笔记 | 二次确认：「结束这场记录？结束后会自动整理成笔记。」[结束并生成笔记] [继续记录] |
| 结束太短 | 时长 < 60 秒：确认文案加一句「这场比较短，可能生成不了要点」；仍允许 |
| 关闭窗口 | 记录中：收进托盘，不询问；空闲：按 `close_action` 偏好（托盘 / 退出） |
| 最小化 | 任务栏最小化，不隐藏到托盘；「最小化到托盘」在更多菜单 |
| 退出 | 见 §5.5 |
| 键盘 | `Space` 暂停 / 继续（非输入状态）；`M` 标记；`Esc` 关闭对话框；结束必须确认 |

**结束确认的默认焦点**：默认聚焦「继续记录」，避免误按 Enter 结束一场长直播；「结束并生成笔记」需要明确点击。

### 4.6 多路

- **恰好 1 路在录**：进入 HUD。
- **≥2 路在录**：不进入 HUD，保留现有「收听」多路视图；顶部一条「2 个直播间正在记录 · 查看记录卡」，点某一路进入该路的 HUD。
- HUD 在多路上下文中显示「还有 1 个直播间在记录」+「切换到多路」。
- 托盘菜单只操作「最近开始的一路」；结束 / 暂停需要确认或明确指向哪一路。
- 不做「一键结束全部」；如果以后做，必须二次确认并说明会结束哪几路。

### 4.7 视觉与动效

| 项 | 规格 |
|---|---|
| 主题 | 默认 studio 深色；支持 paper 浅色；不在 HUD 里写死颜色 |
| 强调色 | 琥珀 / 品牌强调色只用于主按钮和关键状态；红色只用于记录中 / 错误 |
| 计时 | 72–96px，细字重或等宽数字；暂停时降到 40% 不透明度 |
| 状态点 | 记录中红色实心；暂停琥珀空心；断流红色 + 文字；不只靠颜色 |
| 字幕 | 14–15px，行高 1.6；说话人名 12px 大写 / 小字；时间码 12px 弱化 |
| 动效 | 新字幕进入 120ms 上滑；状态点呼吸 1.6s（尊重 `prefers-reduced-motion`） |
| 禁止 | 波形、频谱、粒子、闪烁告警、红色全屏边框 |
| 对比度 | 正文 ≥ 4.5:1；大字 ≥ 3:1；焦点环可见 |

### 4.8 紧凑模式、DPI 与可访问性

- 窗口宽度 < 640px 自动进入紧凑 HUD：隐藏壳导航 / 侧栏；计时 56px；字幕 4 行；操作图标 + 文字；安心条收进更多。
- 125% / 150% DPI 下不截断主按钮；字幕区域可滚动。
- 屏幕阅读器：
  - 计时每分钟播报一次，不每秒播报；
  - 状态变化用 `aria-live="polite"`；
  - 字幕区域 `aria-live="polite"`，但限制频率；
  - 按钮有明确 `aria-label`，图标按钮也不例外。
- 键盘可达：Tab 顺序为状态 → 暂停 → 标记 → 结束 → 字幕 → 更多；焦点环不隐藏。
- 减少动态效果：关闭呼吸、上滑，只保留状态文字变化。

### 5.1 图标状态

### 5.2 Tooltip

### 5.4 行为

| 操作 | 行为 |
|---|---|
| 左键单击 | 显示主窗口；记录中直接落在 HUD；空闲落在首页 |
| 右键单击 | 打开菜单（Windows 习惯） |
| 双击 | 同左键（保留现有） |
| 菜单动作 | 通过 `shell_tray_action` 事件交给壳页调 `/api/live/*`；窗口隐藏时壳页仍存活 |
| 壳页不可用 | Rust 侧直接 HTTP 调引擎兜底，至少保证「暂停 / 结束」可用 |
| 菜单刷新 | 跟随现有诊断轮询（默认 3 秒）；空闲可降到 5 秒；不新增轮询 |
| 托盘重建 | Explorer 重启后自动恢复图标；测试任务栏溢出 / 隐藏图标场景 |

### 5.5 退出与关窗

| 场景 | 行为 |
|---|---|
| 记录中关闭窗口 | 收进托盘，不询问；第一次给一次提示（见 §5.6） |
| 空闲关闭窗口 | 按设置 `close_action`：托盘 / 退出；默认托盘 |
| 记录中退出 | 确认框：**「还在记录，退出会停止录音」** [结束并保存后退出] [仍然退出] [取消]；默认「结束并保存后退出」 |
| 收尾中退出 | 「笔记还在生成，退出会中断生成；录音和逐字稿已保存」[等待完成] [仍然退出] |
| 系统关机 / 注销 | 尽量优雅停止并保存；来不及则下次启动走恢复逻辑；不弹无法操作的对话框 |
| 托盘「退出」 | 同「记录中退出」 |

- 「仍然退出」是破坏性操作，按钮用危险色，并说明「未保存的部分会丢失」。
- 「结束并保存后退出」先走收尾，完成后再退出；如果收尾失败，问「仍然退出？录音和逐字稿已保存」。
- 退出后不能留后台进程；托盘图标消失。

### 5.6 首次收起提示

第一次在记录中关窗时，发一条一次性提示：

> **已收进托盘，录音继续**
> 右键托盘图标可以暂停或结束。

- 只发一次；之后不再提示。
- 如果托盘图标被 Windows 收进 `^` 溢出区，提示里补一句「图标可能在任务栏右下角的 ^ 里」。
- 提供「知道了」；不做「不再提示」勾选，因为本来就只发一次。

### 5.7 托盘边界

| 情况 | 处理 |
|---|---|
| Explorer 重启 | 重新添加托盘图标；菜单状态恢复 |
| 任务栏自动隐藏 | 图标仍可用；tooltip 正常 |
| 图标被用户隐藏 | 无法控制；通知仍可达；首次提示说明 ^ |
| 多显示器 / 不同 DPI | 菜单和 tooltip 跟随系统缩放；不在托盘做自绘窗口 |
| 远程桌面 | 图标存在；通知可能被系统抑制；通知中心兜底 |
| 睡眠 / 恢复 | 计时基于音频时长，恢复后不跳变；断流走通知 |
| 系统通知被关闭 | 托盘菜单和通知中心仍可用 |

## 6. 通知

### 6.1 原则

1. **可行动。** 每条通知都有明确的下一步：打开记录卡 / 打开笔记 / 重试 / 检查问题。
2. **不重复。** 同一事件同一场只发一次；断流按 episode 去重。
3. **不打扰。** 应用在前台且聚焦时，只用应用内 toast + 通知中心；不弹系统通知。
4. **不泄密。** 通知正文不放逐字稿原文；锁屏只显示标题 / 主播名（可再收紧）。
5. **不吓人。** 失败通知必须说明「什么还在」，不显示堆栈、阶段码、错误码。
6. **不重播。** 应用重启后，旧通知不再弹系统 toast；未读仍留在通知中心。

### 6.2 事件矩阵

| 事件 | 触发 | 默认 | 标题 | 正文 | 点击 | 去重键 |
|---|---|---|---|---|---|---|
| 断流 | `last_chunk_ago_s > 30` 持续到 45 秒 | 开 | **听不到声音了** | 《阿哲》已 30 秒没有收到声音，可能断流了。 | 打开记录卡 | `stalled + session + episode` |
| 恢复 | 断流后音频块恢复 | 开 | **声音恢复了** | 《阿哲》继续在录。 | 打开记录卡 | `recovered + session + episode` |
| 连续静音 | 全零音频 > 2 分钟 | 开 | **直播可能静音了** | 《阿哲》已经连续 2 分钟没有声音。 | 打开记录卡 | `silent + session + episode` |
| 直播结束 | 看门狗判定下播 | 开 | **直播可能结束了** | 已停止记录，正在生成笔记。 | 打开收尾 / 笔记 | `ended + session` |
| 笔记完成 | 笔记任务成功 | 开 | **《标题》的笔记已生成** | 3 个要点 · 3 段高光 | 打开笔记 | `note_ready + session` |
| 笔记失败 | 笔记任务失败 | 开 | **笔记没生成成功** | <人话原因>，录音和逐字稿都在。 | 打开笔记 / 重试 | `note_failed + session + task` |
| 引擎异常 | 壳检测到引擎退出 / 重启 | 开 | **记录程序断开了** | 正在尝试恢复；恢复不了可以导出诊断包。 | 检查问题 | `engine_error + incident` |
| 磁盘不足 | 启动 / 收尾时剩余 < 2GB | 开 | **磁盘空间不足** | 还剩 2.1GB，长直播可能存不下。 | 存储设置 | `disk_low + day` |
| 首次收起提示 | 第一次记录中关窗 | 开 | **已收进托盘，录音继续** | 右键托盘图标可以暂停或结束。 | 打开记录卡 | `tray_hint`（终身一次） |
| 关注开播 | 关注 `offline → live` | 开 | **你关注的主播开播了** | 《阿哲》正在直播 · 已开播 3 分钟 | 打开首页关注 / 记录 | `follow_live + follow_id + episode` |
| 自动记录开始 | 自动记录成功启动 | 开（低优先级） | **已自动开始记录** | 《阿哲》正在直播，结束后会自动生成笔记。 | 打开记录卡 | `auto_record + session` |
| 自动记录失败 | 自动记录启动失败 | 开 | **自动记录没开始** | <人话原因> | 打开关注列表 / 重试 | `auto_record_failed + follow_id + episode` |
| 预览就绪 | 5 分钟预览（后续迭代） | 预留 | —— | —— | 打开预览笔记 | `preview_ready + session` |

**明确不发通知**：

- 开始记录成功（用户刚点完，没必要）。
- 暂停 / 继续 / 标记（用户刚操作）。
- 每小时「还在记录」（持续打扰）。
- 正常结束但笔记还在生成（等完成再发）。
- 关注的主播下播（不打扰；首页状态更新即可）。

### 6.3 展示规则

| 应用状态 | 展示方式 |
|---|---|
| 前台且聚焦 | 应用内 toast（右下角，4 秒，最多堆 3 条）+ 顶栏铃铛未读 +1；不弹系统通知 |
| 最小化 / 隐藏 / 不在前台 | Windows 系统通知（toast） |
| 全屏应用 / 游戏 / 专注助手 | 系统可能抑制；应用内通知中心仍记录；不强制抢焦点 |
| 系统通知权限关闭 / 发送失败 | 应用内通知中心兜底；设置页显示一次提示 |
| 应用刚启动 | 不重播历史通知；将旧通知标记为已投递，未读保留在中心 |
| 应用正在收尾 / 生成笔记 | 完成通知延迟到 ready；失败立即发 |

- 系统通知点击：先 `show_main`，再切到目标视图（HUD / 笔记 / 首页关注 / 检查问题）。
- 应用内 toast 点击：同样路由；toast 不自动跳转。
- 通知不抢焦点；不播放自定义声音；使用系统默认提示音（如系统支持关闭）。
- 通知中心与系统通知是同一事件的两种展示，不重复计数。

### 6.4 点击路由

`action_json` 统一携带：

```json
{
  "view": "hud | note | home | follow | diagnostics | storage",
  "session_id": "20261115_2003_ab12",
  "room_id": "rm...",
  "follow_id": 1,
  "t": 754.0,
  "notification_id": 123
}
```

| 事件 | 落点 |
|---|---|
| 断流 / 恢复 / 静音 | HUD（该路） |
| 直播结束 | 收尾进度卡（没有则笔记页） |
| 笔记完成 / 失败 | `/note?session=<id>`；失败页带重试 |
| 引擎异常 | 检查问题 / 诊断页 |
| 磁盘不足 | 设置 → 存储 |
| 关注开播 | 首页关注列表并高亮该行；如自动记录已开始则直接 HUD |
| 自动记录失败 | 关注管理抽屉，高亮该行 |
| 首次收起提示 | HUD |

- 落点不存在（场次被删 / 笔记未生成）：退到首页 / 笔记库，并 toast「这条通知对应的内容不在了」。
- 点击后把该通知标记已读。

### 6.5 去重与冷却

- 数据库唯一索引 `dedupe_key` 保证同一事件只写一次。
- 断流 / 静音按 **episode** 去重：恢复后重新计数，下一次断流是新 episode。
- 同类型同场次 10 分钟内不重复弹 toast；通知中心仍只保留一条。
- 全局 toast 频率：最多 5 条 / 小时；超过只进通知中心，不弹系统通知。
- 引擎重启后不重复发已存在的 `dedupe_key`。
- 通知失败（系统层）不删除记录，`delivered_at` 留空，下次可见；但不在应用重启后重播。

### 6.6 通知中心（最小版）

- 入口：顶栏铃铛；未读数红点；点击打开右侧抽屉（360px）。
- 内容：最近 50 条，按时间倒序；每条显示图标 / 类型色、标题、正文一行、相对时间、未读点。
- 操作：单条点击跳转并已读；「全部已读」；空态「没有新通知」。
- 不做：分组、筛选 tab、搜索、删除单条、批量选择。
- 通知中心是系统通知失败 / 被关闭时的兜底，必须完整。
- 键盘：`Esc` 关闭；上下选择；Enter 打开。
- 存储：引擎 `notifications` 表；壳本地通知（引擎异常 / 托盘首次提示）用 `local:` id，合并展示。

### 6.7 通知设置

设置 → 通知：

| 开关 | 默认 | 说明 |
|---|---|---|
| 录音异常（断流 / 静音 / 引擎异常） | 开 | 记录中最重要的提醒 |
| 笔记生成（完成 / 失败） | 开 | 录完的结果 |
| 关注开播 | 开 | 依赖关注功能 |
| 系统提示（托盘 / 磁盘） | 开 | 低频 |
| 桌面通知总开关 | 开 | 关闭后仍保留应用内通知中心 |
| 通知内容显示直播标题 | 开 | 关闭后只显示「你关注的主播开播了」/「一场直播」 |
| 测试通知 | —— | 发一条测试，验证系统权限 |

- 设置存引擎 `settings` 的 prefs，壳和网页版都能读；不要只存 WebView localStorage。
- 关闭分类只影响新通知；通知中心仍保留历史。
- 「桌面通知总开关」关闭时，顶栏铃铛仍工作；设置页说明两者关系。

### 6.8 隐私与锁屏

- 通知正文不出现逐字稿原文、说话人原话、问题内容。
- 默认显示直播标题 / 主播名；可在设置里关闭，改为通用文案。
- 锁屏通知由 Windows 控制；应用不额外读写锁屏内容。
- 通知历史只存本机；不上传、不同步。
- 诊断包导出不包含通知正文（只含类型 / 时间 / 去重键）。

### 6.9 权限与失败

- 首次需要发系统通知时检查权限；Windows 安装版通常默认允许，开发态可能显示为 PowerShell / 无图标，需在验收中单独测试。
- 权限被关闭：
  - 应用内显示一次提示「系统通知被关闭，事件会留在通知中心」+「打开 Windows 通知设置」；
  - 不重复弹；
  - 应用内通知中心始终完整。
- 系统通知发送失败：写日志、`delivered_at` 留空、通知中心可见；不阻塞录音。
- 专注助手 / 游戏模式抑制通知：不视为失败；通知中心仍记录。
- 通知点击失败（窗口无法显示）：至少打开主窗口；再失败则复制深链到剪贴板？不做，保持简单，记录日志。

## 7. 收尾与笔记衔接

### 7.1 收尾三步

```
结束记录
  → 保存录音、逐字稿落盘
  → 整理说话人（全场重聚类）
  → 生成笔记（总结 + 高光）
  → 笔记 ready
```

进度卡规则：

- 三步全部人话；不显示阶段码、队列位置、token。
- 「可以关掉窗口，完成后通知你」+「后台进行」。
- 不锁死整个应用；只锁当前记录卡的结束操作。
- 完成时：如果用户还停在进度卡，直接切笔记页；如果已离开，发通知。
- 失败时：保留「先看原文」；说明录音和逐字稿都在；提供「重试」。
- 收尾中退出应用：提示会中断生成；录音和逐字稿已保存。

### 7.2 与 HUD / 托盘的衔接

- 点「结束并生成笔记」后，HUD 变成收尾进度卡，托盘 tooltip 变「正在生成笔记…」。
- 收尾中关窗：收进托盘；完成通知照发。
- 收尾完成：如果窗口隐藏，通知「笔记已生成」；点击打开笔记。
- 收尾失败：通知「笔记没生成成功」；点击进入失败页，可重试。
- 收尾中不显示「结束」按钮，避免重复提交。

### 7.3 与首页的衔接

- 结束收尾后回首页：顶部记录条显示「笔记已生成 · 阿哲」+「打开笔记」。
- 下次启动：首页最近笔记出现这一篇。
- 如果用户从托盘「打开最近笔记」：直接进笔记页，不经过首页。

### 8.3 API

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/notifications?since_id=&limit=&unread=` | 壳 / 网页拉通知 |
| POST | `/api/notifications/read` | 标记已读（ids / all） |
| POST | `/api/notifications/deliver` | 壳回写已投递，防重启重播 |
| GET / POST | `/api/settings/prefs` | 通知开关字段（复用现有） |

`GET /api/notifications` 响应：

```json
{
  "notifications": [{
    "id": 123, "type": "note_ready", "session_id": "...",
    "title": "《中小主播的选品与复购》的笔记已生成",
    "body": "3 个要点 · 3 段高光",
    "action": {"view": "note", "session_id": "..."},
    "created_at": "2026-11-15 22:51:02",
    "read_at": null, "delivered_at": null
  }],
  "unread": 3
}
```

- 通知正文只存标题 / 简短原因；不存原话、逐字稿。
- `delivered_at` 由壳回写；应用启动时把 `created_at` 早于本次启动且 `delivered_at` 为空的标记为已投递（不弹 toast），但保留未读。
- 分页 `limit` 默认 50；`since_id` 用于增量轮询。

### 8.4 通知表（沿用 33 §3.9.1）

```sql
CREATE TABLE IF NOT EXISTS notifications (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id   TEXT NOT NULL DEFAULT '',
  type         TEXT NOT NULL,          -- stream_stalled | stream_recovered | silent
                                       -- | live_ended | note_ready | note_failed
                                       -- | disk_low | follow_live | auto_record_*
  title        TEXT NOT NULL,
  body         TEXT NOT NULL DEFAULT '',
  action_json  TEXT NOT NULL DEFAULT '{}',
  dedupe_key   TEXT NOT NULL DEFAULT '',
  created_at   TEXT NOT NULL,
  read_at      TEXT,
  delivered_at TEXT
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_notifications_dedupe
  ON notifications(dedupe_key) WHERE dedupe_key <> '';
CREATE INDEX IF NOT EXISTS idx_notifications_created
  ON notifications(created_at DESC);
```

- 壳本地通知（`engine_error` / `tray_hint`）不进表，用 `local:` 前缀在内存 / 本地存储里合并展示；重启后不重播。
- 每日清理：保留最近 90 天 / 500 条，避免无限增长。

### 8.5 托盘动作协议（沿用 33 §3.9.2）

```json
{ "action": "hud" | "pause" | "resume" | "mark" | "finish" | "recent_note" | "quit_confirm" }
```

- 壳收到后调对应 `/api/live/*`；成功后下一轮轮询自然刷新托盘。
- `quit_confirm` 由壳弹确认；用户确认后调用 Tauri 退出命令。
- 壳页不可用（引擎已退出 / 页面重载）：Rust 侧对 pause / resume / finish 直接 HTTP 兜底，至少保证能停。

### 8.6 通知投递流程

```
引擎事件
  → notify.emit(type, session, dedupe_key)
  → notifications 表（唯一索引去重）
  → 壳每 3–5 秒 GET /api/notifications?since_id=...
  → 应用前台？ → 应用内 toast + 铃铛
  → 应用后台？ → Windows toast（tauri-plugin-notification）
  → POST /api/notifications/deliver 标记已投递
  → 点击 → show_main + 路由 action_json
```

- 壳隐藏时仍在运行，轮询继续；不要因为窗口隐藏停止通知。
- 应用完全退出时无法通知；下次启动不补发旧 toast。
- 系统通知失败不阻塞引擎；`delivered_at` 留空，中心可见。

## 9. 边界与异常

| 情况 | 期望行为 | 不做什么 |
|---|---|---|
| 系统睡眠 / 恢复 | 计时按音频时长，不跳变；恢复后若断流，45 秒内通知；自动重连 | 不把睡眠时间算进录音 |
| 网络切换 / 断网 | 断流提示 + 通知；恢复后「声音恢复了」；不自动结束 | 不静默继续显示「正在记录」 |
| 引擎崩溃 | 壳显示「记录程序断开了」；尝试恢复；已落盘音频保留；通知一次 | 不谎称「录音还在」 |
| 磁盘满 | 2GB 预警；200MB 以下停止并保存；HUD + 通知说明 | 不直接崩溃 / 不丢已录部分 |
| Windows 关机 / 注销 | 尽量优雅保存；下次启动恢复 | 不弹无法操作的对话框 |
| 时钟变化 / 时区 | 计时用 `elapsed`，不用墙钟；通知时间用本地时间 | 不让计时倒退 / 跳变 |
| 多显示器 / DPI | 托盘、HUD、通知中心随系统缩放 | 不自绘托盘窗口 |
| Explorer 重启 | 托盘图标恢复；菜单可用 | 不要求重启应用 |
| 通知权限关闭 | 应用内提示一次 + 通知中心兜底 | 不反复弹权限请求 |
| 专注助手 / 游戏模式 | 系统抑制通知；中心仍记录 | 不绕过系统设置 |
| 同一秒多个通知 | 合并为最多 3 条 toast；其余进中心 | 不刷屏 |
| 长直播（> 2 小时） | 计时、字幕、内存稳定；收尾分层抽样 | 不在 HUD 显示 token / 队列 |
| 超短场（< 1 分钟） | 允许结束；提示可能没有要点；仍生成基础笔记 | 不阻止用户 |

## 10. 验收清单

### 10.1 HUD

- [ ] 开始记录后 3 秒内进入 HUD；状态行显示「正在记录」。
- [ ] 计时与音频时长一致；暂停时停住；继续后从暂停点继续。
- [ ] 暂停 30 分钟的应用内提醒只出现一次，不发系统通知。
- [ ] 字幕显示最近 6–8 句定稿 + 识别中；新句从底部进入；不做表格。
- [ ] 标记此刻写入成功，toast 显示时间码；最近 3 个标记可见。
- [ ] 结束确认默认聚焦「继续记录」；确认后进入三步收尾。
- [ ] 断流时 HUD 显示红色人话提示 + 重新连接 / 结束并保存。
- [ ] 安静 30 秒只提示，不发通知；连续静音 2 分钟才发。
- [ ] 直播结束提示「可能」+ 继续记录兜底。
- [ ] 生成失败显示人话 + 重试 + 先看原文；录音和逐字稿不丢。
- [ ] HUD 无波形、阶段码、token、重叠秒数、房间列表。
- [ ] 紧凑模式 <640px 可用；125% / 150% DPI 不截断。
- [ ] 键盘 Space / M / Esc 可用；屏幕阅读器不每秒播报计时。

### 10.2 托盘

- [ ] 关窗后录音继续；5 分钟后仍有新定稿。
- [ ] 托盘 tooltip 显示正确计时；暂停 / 断流 / 收尾状态正确。
- [ ] 左键打开 HUD；右键菜单可用；双击同左键。
- [ ] 托盘暂停 / 继续 / 标记 / 结束在窗口隐藏时可用。
- [ ] 结束需要确认；取消后录音不中断。
- [ ] 退出有录音时确认；「取消」不中断；「仍然退出」明确说明丢失风险。
- [ ] 第一次关窗收到一次「已收进托盘」提示；之后不再出现。
- [ ] Explorer 重启后托盘图标恢复。
- [ ] 多路时只操作最近一路，且有「切换到多路视图」。

### 10.3 通知

- [ ] 断流 45 秒内收到系统通知；恢复收到恢复通知；同一 episode 不重复。
- [ ] 应用前台时只出应用内 toast，不弹系统通知。
- [ ] 笔记完成通知点击直接打开对应笔记。
- [ ] 笔记失败通知说明「录音和逐字稿都在」+ 重试。
- [ ] 引擎异常通知点击打开检查问题。
- [ ] 磁盘不足通知每天最多一次。
- [ ] 通知正文不含逐字稿原文；隐私开关关闭标题后生效。
- [ ] 系统通知权限关闭时，通知中心仍完整；提示只出现一次。
- [ ] 重启应用后不重播旧通知；未读仍在中心。
- [ ] 通知中心「全部已读」、单条跳转、键盘操作可用。
- [ ] 通知设置分类开关生效；总开关关闭后中心仍工作。

### 10.4 收尾衔接

- [ ] 结束后三步进度人话显示；可「后台进行」；不锁全应用。
- [ ] 完成时用户在进度卡 → 直接进笔记页；不在 → 发通知。
- [ ] 失败可重试 / 先看原文；录音和逐字稿都在。
- [ ] 收尾中退出有确认；录音和逐字稿已保存。
- [ ] 托盘「打开最近笔记」直达笔记页。

## 13. 不做什么

- 独立置顶小窗、悬浮 pill、桌面歌词式 HUD（P1 再评估）。
- 波形 / 频谱 / 音量表（记录中不需要）。
- 直播画面常驻、弹幕、礼物、观众数。
- 多路批量暂停 / 结束 / 一键全停。
- 通知分组、筛选、搜索、自定义声音、自定义免打扰时段（跟随系统专注助手即可）。
- 邮件 / 短信 / 手机推送 / 云同步。
- 录屏、视频切片、视频下载。
- 每小时「还在记录」的提醒。
- 在 HUD 里编辑逐字稿 / 说话人 / 分类。
- 在通知正文里放逐字稿原文。

| 4 | 应用前台时弹系统通知吗？ | **不弹**，只应用内 toast + 中心 | 避免双重打扰；系统通知留给离开场景 |
| 5 | 重启后补发旧通知吗？ | **不补发系统 toast**，未读保留在中心 | 旧事重提是噪音 |
| 6 | 多路怎么办？ | **1 路 HUD，≥2 路现有收听多路视图**；托盘只操作最近一路 | 避免一个计时器混淆多路；批量操作后置 |
| 7 | 断流阈值？ | **30 秒判定，45 秒内通知** | 与现有看门狗一致；给恢复留时间 |
| 8 | 静音提醒？ | **连续 2 分钟全零才通知**；30 秒只 HUD 轻提示 | 冷场不是故障，避免误报 |
| 9 | 收尾自动生成笔记吗？ | **是**，结束即生成 | 「结束并生成笔记」是一个承诺 |
| 10 | 通知中心要不要？ | **要，最小版** | 系统通知可能被关 / 被专注助手抑制；必须兜底 |

---

## 15. 一句话总结

**HUD 回答「在录吗」，托盘回答「还在录吗」，通知回答「出事了 / 出结果了」。** 三者一起，用户才敢把两小时的直播交给它，而不是开着窗口盯着波形。
