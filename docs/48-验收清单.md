# 48 · 这一轮更新的验收清单

> 面向：产品自测
> 结论时间：2026-11-26
> 说明：这份是「你自己怎么看到功能」的操作手册。**不需要懂代码**，按顺序做即可。

## 0. 先说清楚：功能加在哪了

这一轮的东西**不在桌面网页上**，全部在**飞书的机器人对话里**。

因为云端这台机器只有 701MB 内存、只做录音，桌面端那套完整界面（播放器、逐字稿、
拖拽改名）在云上跑不起来。所以产品形态是：

| 你在哪 | 能做什么 |
|---|---|
| 桌面端网页（本机 `run.py`） | 编辑室：逐字稿、时间轴、说话人重聚类、校对 |
| **飞书机器人（手机上）** | 刊物 + 索引：读总结、找人、搜原话、问问题、看云文档 |

**所以验收基本都在飞书里做。** 打开飞书，找到那个机器人（app_id 以 `cli_aa668e` 开头），
私聊它即可。

## 1. 五分钟能跑完的检查（不需要任何配置）

### 1.1 机器人还活着

```
/状态
```

**正常**：回几条房间的状态（哪路在录、断了多久、补转写进度）。
**失败**：没回复 → 机器人进程挂了，看 `journalctl -u livenotes-feishu`。

### 1.2 帮助菜单里能看到新命令

```
/帮助
```

**检查**：回出来的长文本里，**必须有这四行**：

```
/找人 阿哲 看这个人的观点档案
/搜 OPC政策 找结论和原话（带时间码与文档链接）
/问 阿哲怎么看 OPC？ 用笔记回答问题并给引用
/补名 [CH] 给上麦的人补名字（试听 + 表单卡）
```

没有这四行 = 云端跑的还是旧机器人。

### 1.3 搜索原话（这一条最能说明新功能真的通了）

```
/搜 FDE
```

**正常**：回 5 条原话，每条带 **时间码 + 说话人 + 文档链接或「未发布」**。
例如「…FDE就是咱们直播间一直在讨论…」这种。

**为什么要测这条**：它串了三个新东西——关键词扩展、跨场检索、发布台账查询。
它通了，说明读侧整条链路是活的。

**失败的情形**：
- 回「还没有可搜的场次」→ 云端库里没逐字稿（不该发生，现在有 5 场 7112 句）
- 回「服务没起来」→ 引擎挂了，但它会回退到本地库，仍应有结果

### 1.4 问一个问题

```
/问 这场直播主要聊了什么
```

**正常**：回一段答案，**带引用出处**（第几场、什么时间）。
**注意**：这条会真调大模型，需要 10~30 秒；后台轮询，不是卡住。

### 1.5 找人（预期会"没有"）

```
/找人 阿哲
```

**正常但会说没有**：因为现在**一个人都没命名**（云端 `persons` 表是 0 条）。

这不是 bug，是设计：**人物档案按需生成，但前提是这个人被命名过**。
现在所有说话人都是「嘉宾3」「说话人7」这种槽位名，不构成"人"。

**这一条想让你看到的正是问题所在**——见下面 §3。

### 2.2 要开的话，按这个顺序

**第一步：确认权限（已完成）**

开放平台 → 权限管理里这些应为「已开通」，并且「版本管理与发布」里点过发布：

- `bitable:app`（场次表、观点表）
- `docx:document`、`docx:document:create`、`docx:document:readonly`
- 云空间上传/授权相关（`drive:file` / `drive:permission`）

**第二步：确认开关**

有 `app_id` / `app_secret` 时发布默认开启；如果 `livenotes.env` 里显式写过
`FEISHU_PUBLISH_ENABLED=0`，改成 `1` 或删掉这一行。然后更新代码并重启：

```bash
cd /opt/livenotes && git pull
bash restart-engine.sh          # 引擎（别直接 systemctl restart livenotes-engine）
systemctl restart livenotes-feishu
```

**第三步：发布一场试试**

```
/发布 CH01
```

再 `/文档 CH01` 看结果。

**正常应该看到**：
- 飞书里多了一篇云文档，标题像「11-26 18:42 · AI狂人斌哥 · 开源AI聊天室」
- 正文有：一句话、观点地图、值得回听、人物、相关场次、录音
- 文档权限自动给了你（`owner_open_id`）
- 场次表里多一行，带文档链接、录音链接、逐字稿链接
- 云空间 `FEISHU_AUDIO_FOLDER_TOKEN` 下多一个 `日期_HHMM_房间名/` 文件夹，
  里面有这一场的 `标题.m4a` 和同名 `.txt` 逐字稿
- 场次表该行的「录音」「逐字稿」附件字段能点开或下载

**如果只建了文档、表格失败**：`state=partial`，文档仍可读，重试只补表格，不会重写正文。

**如果附件是空的**：文档和场次表仍算成功；看 `feishu_publish.meta_json` 里的
`base_attach_error` 和日志 `feishu.base_attach_failed`。常见原因是租户不允许
`type=17` 附件字段或 media 上传被拒；代码会自动退回链接列，不会让整行失败。

想单独确认「附件字段到底能不能用」，在服务器上跑一次探针（临时字段/临时行，跑完自动删）：

```bash
cd /opt/livenotes && .venv/bin/python tools/spike_base_attachment.py
```

- 退出码 0、最后一行「✓ 附件字段可用（2a）」= 附件链路通；
- 退出码 1 = 这个租户建不出/写不进附件字段，退回链接列是正确行为，不用再查。
  加 `--keep` 可以留着临时现场自己去 Base 里看。

历史场次补附件：再发一次 `/发布` 即可（机器人命令默认 `force=True`，会重写正文并补齐
「录音」「逐字稿」；media token 有缓存，不会重传大文件）。
云空间里的老录音用 `tools/backfill_drive_folders.py` 迁进各自文件夹。

### 2.2.1 只想先看文档：`FEISHU_PUBLISH_BASE=0`

场次表只是「索引」，不写它发布照样成立。在 `livenotes.env` 里多写一行：

```
FEISHU_PUBLISH_BASE=0
```

效果：**只建云文档、不碰多维表格**，`state` 直接是 `ok` 而不是 `partial`，
不会再有「场次表没写成功」的警告。代价是手机上少一张能按房间/日期排序的表，
`/文档`、文档正文、`/找人`、`/搜`、`/问` 全都照常。

**建议**：权限已经开了，直接用默认的两张表；这条只作为排障开关保留。

## 3. 我认为你现在最该看的一件事：命名

产品设计里写着一句话，我转述一下：

> **跨场人物能力 = 命名率的函数。**

意思是：不补名，"阿哲"永远是"本场第 3 位上麦者"。那么：

- 人物档案永远是空的（`/找人` 会说没有）
- 观点地图只有槽位名，看不出是谁说的
- 改口追踪做不了（"他上周说 A，这周说 B" —— 不知道"他"是谁）
- 场次文档里的人物表全是「嘉宾7」

**这不是功能没做完，是产品的一个前提条件没满足。**

现在能看到的具体情况：5 场、7112 句逐字稿、8 条观点、**0 个人物**。

### / 补名 怎么用

```
/补名 CH01
```

机器人会：
1. 列出这场发言最多的前 5 位
2. 每人发一段 **3 秒试听音频**
3. 发一张表单卡，选 A/B/C 填名字
4. 文字兜底也行：`1 阿哲 2 小北`

填完之后：当场文档会更新，而且这个人的**历史场次**会由后台回填。

**这一条是我最建议你先试的。** 试完再看 `/找人 阿哲`，就能看到档案了。
